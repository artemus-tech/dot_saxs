# Правила работы в этом репозитории

## Перед работой

- Прочитать SPEC.md (ТЗ), DECISIONS.md (решения и изменения ТЗ — важнее SPEC.md) и последний отчёт в `reports/`.

## Как писать пользователю

- По-русски, коротко, простыми словами. Без пересказов и повторов: токены пользователя не тратить зря.
- Термин (`rowvar`, broadcasting, view…) — только с объяснением в несколько слов.
- Вопрос — сначала суть одной фразой: «У `np.cov` есть скрытый параметр `rowvar`, он работает как `axis`.
  Убираем или оставляем как в NumPy?» Пример — после, короткий, с числами.
- Если ответ следует из уже принятого решения (DECISIONS.md) — не спрашивать, а применить и сказать одной строкой.
- Один вопрос — одна тема, не больше трёх вопросов за раз.
- Варианты — только когда просят; иначе одно предложение с рекомендацией.
- Примеры кода — в принятом стиле API: `Vector`, `Matrix`, `CubeMatrix`, `GetRow(…)`, LINQ; без `^1`.

## Код и отчёты

- Сдавать только то, что собирается с предупреждениями как ошибками и проходит все тесты (SPEC.md, п. 0).
  Сборка и тесты идут в GitHub Actions (DECISIONS.md, п. 2).
- Коммиты, отчёты и документация — по-русски.
- Отчёт: что сделано / что проверено в цифрах / что дальше.
